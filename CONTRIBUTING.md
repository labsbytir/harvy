# Contributing to Harvy

The canonical contribution and engineering policy is [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md). Read [AGENTS.md](AGENTS.md) for agent-specific entry instructions and [docs/ROADMAP.md](docs/ROADMAP.md) for implementation status.

1. Link an issue or authorized user task with observable acceptance criteria.
2. Record the OpenChamber task, repo/base revision, owner, and isolated branch/worktree.
3. Follow the shared contracts, source/access policies, and code conventions in the engineering standard.
4. Include meaningful tests, canonical documentation, migrations/recovery where applicable, and exact validation evidence.
5. Use the PR template, resolve review findings, and obtain independent approval on the final revision before merge.

See [preflight and submission requirements](docs/DEVELOPMENT.md#16-preflight-lint-and-submission-procedure) for detailed steps and [adoption status](docs/DEVELOPMENT.md#17-adoption-status-and-verified-gaps) for checks that still need implementation. Do not claim the full standard is enforced merely because existing tests pass. Report vulnerabilities through [the security reporting guide](docs/SECURITY_VULNERABILITY_REPORTING.md), without posting secrets or private records publicly.
